## 3. Forward-test guards

**H1 and H2 (`scripts/forward_test.py`, `docs/prereg/FORWARD_TEST.md`): VERIFIED.**

* A dry run that reaches past 2 November 2026 is refused: `--dry-run --start 2026-10-01 --end 2026-11-04` gives `a dry run may use past data only (end on or before 2026-11-02)`.
* A forward run with any start other than 3 November 2026 is refused: `--start 2026-11-04` gives `the pre-registered forward test starts on 2026-11-03`.
* The stopping rule is enforced from the data, not from the user: H1 is computed only after 130 negative Pro GEX days or 31 December 2029, H2 only after 100 counting weeks, 31 December 2028 or an expiry-weekday change. A forward run with `--start 2026-11-03 --end 2026-11-03` (output in scratch, which the pre-registration's section 7 allows because it prints counts only) reported for both hypotheses "stopping point not reached", "not computed": H1 has 1 day, 0 with negative Pro GEX; H2 has 0 counting weeks. No coefficient, p-value or variance comparison was printed.
* The unit tests `tests/test_forward_test.py` and `tests/test_live_dry_run.py` pass (22 passed), including `test_forward_mode_reports_counts_only_before_the_stopping_point` and `test_command_line_refuses_windows_that_break_the_preregistration`.
* Data checks from that run (allowed): minute bars match NSE's high, low and open within 5 bp on 3 November; the 15:29 bar equals the official close; the rebuilt GEX panel matches the committed `results/pipeline_nse_v2` on all 29 overlapping days (difference 0, no sign or expiry-label mismatches).

**Small finding.** The script's auction check counted 0 of 1 days as "15:15 to 15:27 frozen at the 15:15 close". The closes from 15:15 to 15:28 on 3 November are all 23,731.85, so the index did freeze; the check fails only because the 15:15 bar itself has a 0.10-point range (low 23,731.75, high 23,731.85). Section 2 of the pre-registration says the 15:15 bar is "a single price"; on 3 November that was not exactly true. It does not affect H1 or H2, which use closes only, but the count will understate frozen days.

**Watch item for H2.** The next NIFTY expiries are on Mondays 9 and 23 November. H2's counting rule accepts a Monday only when the Tuesday after it is an exchange holiday. If Tuesday 10 or 24 November turns out to be a trading day, `expiry_rule_change` would stop H2 at once. These Tuesdays are expected to be NSE holidays (Diwali Balipratipada and Guru Nanak Jayanti), but that was **NOT VERIFIED** here.
